Build your CV site, one decision at a time

Every step follows the same rhythm: Learn the idea, Do the task, Test your work, then Correct anything that failed.

How to use it: read the Learn section, tick the Do tasks as you type your own version, press Test this step to check, then use the Correct panel to fix what failed. Open my project at the bottom of the screen to type your files, see a live preview, and run every check. Your ticks and code are saved in this browser.

Note: The worked examples use “Your Name” and “Your University” as placeholders. Replace these with your own details, but never put sensitive personal information (full address, phone number, date of birth) in a public CV site.

1Create your folders

Learn

A predictable structure means your HTML can always find your CSS and images. A broken path is the most common reason a site appears unstyled.

  • Lowercase filenames, no spaces. The UCL server is case-sensitive, Windows is not. Profile.JPG works on your laptop and 404s online.
  • Relative paths only: static/styles.css, never C:\Users\you\....
  • Your href must match the real folder. Accepted paths: css/style.css, static/style.css, static/styles.css, or styles.css.

          5Add images correctly

          Learn

          An image needs four things to work well: the right relative path, descriptive alt text, width and height so the page does not jump while loading, and a CSS rule so it never overflows on a phone.

          Image checklist
          AttributeWhy it matters
          srcRelative path into images/. Lowercase, no spaces.
          altDescribes the image's purpose for screen-reader users. Never leave empty unless the image is purely decorative.
          width and heightReserve space so the layout does not shift while the image loads.
          CSS max-width: 100%Stops large images overflowing on small screens.

          How to add your own image: save the file in the images/ folder using lowercase letters and no spaces (e.g. profile.jpg), then point src at it with a relative path. If the image is decorative only, use alt=""; otherwise describe what it shows.

                    10Your 750-word commentary

                    Learn

                    Markers reward why, not what. Think of the commentary as a map of your decisions.

                    Suggested word budget
                    PartAboutCover
                    Introduction75Purpose, audience, what you built
                    Design and planning175Colour, type, layout, folder structure, and the reasons for each
                    Technical implementation300Semantic HTML, table, contextual selectors, variables, responsiveness
                    Challenges125What went wrong and how you fixed it
                    Evaluation75What works, what you would change
                    1. Gather evidence. Write one sentence for: folder structure, semantic tag, table choice, CSS variable, contextual selector, media query, one challenge.
                    2. Introduction (~75 words). Purpose, audience, what you built.
                    3. Design and planning (~175 words). Every sentence must have a “because”.
                    4. Technical implementation (~300 words). Name specific elements and properties.
                    5. Challenges (~125 words). One real problem and your fix.
                    6. Evaluation (~75 words). What works, what you would change.
                    7. Attribution. Cite anything borrowed and say what you changed.
                    8. Check word count and “because” count. Aim for 650–850 words and at least 8 “because”.

                      ↗Deploy to the UCL server

                      Learn

                      Your site is built and validated locally. Now you need to put it on a server so a marker can see it. UCL uses different hosting systems depending on your department. This guide covers the most common scenario for a hand-coded static site: your personal web space.

                      Do

                      1. Go to https://my.desktop.ucl.ac.uk/ and log in with your UCL credentials. Install Citrix Receiver if prompted.
                      2. On the UCL Desktop, open Start → All Programs → Utilities → Mount Unix Filestore (T-drive).
                      3. Open the T: drive. Look for a folder called html.pub. If it does not exist, create it.
                      4. Copy your entire cv-site folder (including static/ and images/) into html.pub.
                      5. Run Start → All Programs → Utilities → Publish Web Pages and point it at html.pub to make files publicly readable.
                      6. Open http://www.homepages.ucl.ac.uk/~youruserid/cv-site/index.html in a private window.
                      If your course uses Silva CMS instead: log in via the grey cross at the bottom-right of the page, then upload files through the Contents screen. Ask your tutor which system your department uses.
